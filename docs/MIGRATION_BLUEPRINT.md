# FeiFeiCMS ThinkPHP 8 升级蓝图

## 1. 源码结论

用户提供的归档标签是 `4.4.201206`，但 `Lib/Lang/zh-cn/common.php` 内部版本为 `4.3.201206`。源码基于 ThinkPHP 2.1 风格，包含 195 个 PHP 文件、19 张 MyISAM/utf8 表、四个旧应用分组（Home、Admin、Crontab、Plus）和四套模板目录。

旧站功能不只是“影片列表”：还包括影片/资讯/专题/演员/角色、评论与留言、用户和付费、卡密与订单、采集源、播放器、静态生成、定时任务、图片管理、模板管理、微信入口及 JSON API。把首页和详情页跑起来不等于迁移完成。

## 2. 技术决策

| 层 | 选择 | 原因 |
|---|---|---|
| PHP | 8.2–8.5，容器基线 8.5.10 | 覆盖仍受支持的 PHP 8 系列，并实际面向当前最新版验收 |
| 框架 | ThinkPHP framework 8.1.4 | 当前稳定核心；不用已停止维护的 TP2/TP3 |
| 数据库 | MySQL 8.4 LTS | 生产稳定线；迁为 InnoDB、utf8mb4、严格模式 |
| 缓存/会话 | Redis 8，文件降级 | 缓存、会话、限流和任务锁分层使用，不把 Redis 当数据库 |
| 搜索 | Meilisearch 1.x，MySQL 降级 | 中文容错、相关性、部署和 API 体验优于旧 Xunsearch；通过接口可再加 Xunsearch |
| 模板 | 新 Think 模板 + 旧标签适配层 | 禁止直接运行 TP2 编译缓存；逐标签验证第三方模板 |
| 部署 | Nginx + PHP-FPM + Compose | 可重复构建、健康检查、最小权限和独立持久卷 |

## 3. 新程序的稳定契约

### 数据

- 正式表使用 `ffx_` 前缀；旧 `ff_*` 只允许作为一次性导入源。
- 时间使用 UTC `DATETIME(6)`；展示层按用户时区转换。
- 影片、季度、播放线路、分集和媒体资源独立建模并使用外键。
- 多分类、标签、人物和专题均使用关系表，禁止逗号 ID 和下标耦合。
- 采集去重使用 `provider + entity_type + external_id`，不能只按标题覆盖。

### URL 与接口

- 新页面使用稳定资源 ID；旧样式 URL 只是可选别名，不影响内部模型。
- `/api.php/provide/vod/` 保留 `ac`、`t`、`pg`、`wd`、`ids`、`h` 参数。
- API 字段命名仍使用 `vod_id`、`vod_name`、`vod_play_from`、`vod_play_url` 等常用采集契约。

### 模板

- 原模板只作为输入资产，不直接 `include` 或执行旧编译产物。
- 第一阶段支持基础变量、循环、条件、URL、影片/分类列表；采集、任意 PHP、模板文件写入不进入前台渲染权限。
- 每套模板至少验收首页、分类、搜索、详情、播放、移动端和错误页。

## 4. 数据库建设

1. `database/schema.sql` 在空 MySQL 8.4 建立 45 张 InnoDB/utf8mb4 表。
2. `ffx_schema_versions` 记录结构版本，`feifei:schema:install` 幂等执行。
3. 外键维护实体关系，组合索引针对前台列表、后台筛选、队列领取和审计查询。
4. 管理员只写入 `password_hash()` 结果；角色与权限使用关系表。
5. 旧库导入作为独立工具实施：读取旧库、转换、写新库、记录映射、抽样对账，不设置长期双写。

## 5. 缓存与搜索边界

Redis 键按用途分区：

- `page:*`：短期页面/查询缓存。
- `session:*`：管理端和用户会话。
- `rate:*`：接口、登录和搜索限流。
- `lock:*`：采集、索引、静态生成互斥锁。
- `queue:*`：后续异步任务。

搜索写入采用“数据库成功后异步索引”，数据库始终是事实源。Meilisearch 故障时读取自动降级 MySQL；后台显示索引滞后数量与最后同步错误。相关性排序由搜索引擎给出的 ID 顺序保持，不能再被 MySQL `vod_addtime` 覆盖。

## 6. 安全重构

- 所有 SQL 由 ORM/参数绑定执行，废弃 `mysql_*` 与字符串拼 SQL。
- 管理端使用强密码哈希、会话轮换、CSRF、登录限流、操作审计和权限矩阵。
- 上传按 MIME、扩展名、尺寸和随机文件名校验；上传目录禁止 PHP 执行。
- 采集器增加目标白名单、内网地址阻断、超时、大小限制和 SSRF 防护。
- 模板编辑、数据库执行、远程下载和支付回调默认关闭或改为受审计的专用流程。
- 响应增加 CSP、`nosniff`、Referrer-Policy 和 frame 限制；生产环境不显示栈和 SQL。

## 8. 明确不做的危险捷径

- 不把旧 TP2 框架改到“勉强不报错”后称为最新版框架。
- 不在 PHP 8 中直接运行旧模板编译缓存。
- 不把语法检查当作 MySQL、Redis、搜索、真实 HTTP 或播放器验证。
- 不把兼容接口的旧字段反向扩散到数据库和业务模型。
